# ReadMe.ai

An AI reading companion. Upload a book, read it in a calm, distraction-free
reader, and select any word, sentence, or passage to get an explanation
grounded in the surrounding text — without leaving the page.

| Component | Path | Stack |
| --- | --- | --- |
| Backend API | [`apps/api`](apps/api) | Python 3.12, FastAPI, SQLAlchemy 2 (async), Alembic, PostgreSQL |
| Mobile / web client | [`apps/mobile`](apps/mobile) | Flutter, Riverpod, go_router, Dio |
| Local stack | [`infra/docker`](infra/docker) | Docker Compose: API, PostgreSQL, Qdrant, Ollama |

## What it does

- **Library** — upload **PDF, EPUB, Markdown, or plain-text** books (50 MiB by
  default). Each upload is processed into a structured document
  (chapters → sections → paragraphs → sentences) and its status moves from
  *Processing* to *Ready* or *Failed*.
- **Reader** — reflowable text with adjustable font size, line spacing, and
  light/dark mode. Your position is saved automatically and restored when you
  come back; bookmarks save places you want to return to. Positions use stable
  character-offset anchors, never page numbers, so they survive font changes.
- **Explanations** — select text and tap *Explain*. The backend decides whether
  the selection is a word, sentence, or passage and answers accordingly
  (meaning + example for words, plain-English meaning for sentences, the
  author's intent for passages), and may suggest prerequisite concepts.
  Explanations are generated by a local LLM through [Ollama](https://ollama.com).

## Quick start (local, no Firebase needed)

Development authentication lets you run everything locally with a mock user.
It is refused at start-up when `APP_ENV=production`.

```bash
# 1. Backend stack (API + PostgreSQL + Qdrant + Ollama)
cp .env.example .env                  # then set DEV_AUTH=true in .env
docker compose --env-file .env -f infra/docker/docker-compose.yml up --build
```

The API is served on <http://localhost:8000> (interactive docs at `/docs`).
Database migrations are applied automatically on start. The first run also
downloads the language model (`OLLAMA_MODEL`, a few GB); explanations return
a `503` until it finishes, and everything else works immediately.

```bash
# 2. Client (web shown; any Flutter device works)
cd apps/mobile
flutter pub get && flutter gen-l10n && dart run build_runner build
flutter run -d chrome --web-port 8080 --dart-define=DEV_AUTH=true \
  --dart-define=API_BASE_URL=http://localhost:8000
```

`--web-port 8080` matches the default `CORS_ALLOW_ORIGINS`; if you serve the
web client elsewhere, add that origin to `.env`. On an Android emulator use
`API_BASE_URL=http://10.0.2.2:8000` (the emulator's alias for your machine).

Using real accounts instead: leave `DEV_AUTH=false`, set `FIREBASE_PROJECT_ID`
for the API, and pass the Firebase `--dart-define` values described in
[`apps/mobile/README.md`](apps/mobile/README.md).

## Architecture in brief

```
Flutter client ──HTTPS + Firebase ID token──▶ FastAPI (apps/api)
                                                ├─ auth         verify token, provision user
                                                ├─ library      upload / list / delete books
                                                ├─ processing   PDF · EPUB · text → structured document
                                                ├─ reader       content, progress, bookmarks
                                                ├─ explanation  classify selection → strategy → LLM
                                                └─ learning     learner-aware capabilities (prerequisites)
                                              PostgreSQL · local/object storage · Ollama
```

- Every product endpoint is authenticated and scoped to the caller: another
  user's book is indistinguishable from a missing one (`404`).
- Errors share one envelope: `{"error": {"code", "message", "details",
  "request_id"}}`. The `X-Request-ID` response header matches the id in the
  server logs.
- Processing never fails an upload; its outcome is recorded on the book and
  can be retried with `POST /api/v1/books/{id}/processing`.

## Quality gates

CI runs on every pull request touching each app:

```bash
# Backend (apps/api)
ruff check . && black --check . && isort --check-only . && mypy app && pytest
alembic upgrade head && alembic check     # against PostgreSQL in CI

# Client (apps/mobile)
dart format --set-exit-if-changed . && flutter analyze && flutter test
```

Pre-commit hooks for both are configured in
[`.pre-commit-config.yaml`](.pre-commit-config.yaml) (`pre-commit install`).
